# Feluqa platform: current baseline and target

**Authority:** the owner-designated [Monorepo Architecture](../02.architecture/01.monorepo-architecture.en.md), [Product Document](02.intent.en.md), and [Compilation requirements](../02.architecture/02.compilation-and-targets.en.md) take precedence over every other documentation page. This page summarizes their target direction alongside a factual implementation inventory reviewed 2026-10-28. Target architecture is normative direction; it does not claim unimplemented software is delivered. No runtime tests were rerun for the documentation migration.

Feluqa is a proprietary Rust platform and unified namespace for web, workstation,
mobile, games, APIs and real-time systems. Shared schemas and tooling support
separate runtime profiles. Web delivery is the first priority. One business module
serving hosted web and a standalone workstation is a target, not a delivered
cross-platform runtime.

## Targets and limits

[Target] Installable modules, per-domain licensing, deploy/restore qualification,
resource-driven application generation, complete panels, production Live, BI and
web/workstation products require the acceptance work in the [roadmap](03.roadmap.en.md).
Desktop runtime, local storage topology, offline writes, synchronization and
conflict handling are not selected. OIDC, agent principals, MCP, native shells
and one-command deployment in the product proposal are not shipped capabilities.

The canonical monorepo architecture now resolves workspace layout, crate grouping,
core/no_std direction, system panel, UI layers, native shells and WASM component
modules as target architecture. The current flat workspace, crate ownership and
feature graph are migration inputs, not competing architecture decisions. Registry
trust, sync semantics, offline license behavior and agent approval defaults remain
open where the canonical product document says so.
