# Dependency review policy

Every first-party Cargo package with direct dependencies must have an English
`DEPENDENCIES.md` beside its `Cargo.toml`. The file is package-specific and
records why each direct dependency is present, which features are enabled, and
what was checked. It is not a copy of Cargo metadata and does not replace the
workspace lockfile.

## Required review record

For each direct runtime, build and development dependency, record:

- the package and the feature or target that activates it;
- the concrete use in the package, its owning API, and why the standard library
  or an existing Feluqa crate is insufficient;
- selected features and defaults intentionally disabled or enabled;
- upstream project/docs, maintenance and maturity evidence reviewed, and the
  locked version;
- declared license, MSRV and target support, checking Cargo metadata and the
  upstream package source rather than assuming compatibility;
- a review of the direct/transitive feature tree and notable native/build
  dependencies;
- checks actually run, with date/toolchain and any unavailable audit tools;
- known gaps, including unrun advisories, license scans, provenance checks or
  cross-platform builds.

Do not call a dependency safe, audited or approved merely because it compiles
or has a permissive license. Avoid unmaintained, unnecessary, duplicate or
network-fetching build dependencies. Prefer the narrowest feature set and
runtime boundary. Inspect dependency updates in the lockfile and rerun the
package's compile/tests and supply-chain checks appropriate to the change.

## Minimum change review

```sh
cargo tree --manifest-path _crates/Cargo.toml -p <package> -e features
cargo tree --manifest-path _crates/Cargo.toml -p <package> --duplicates
cargo check --manifest-path _crates/Cargo.toml -p <package> --all-targets --locked
cargo test --manifest-path _crates/Cargo.toml -p <package> --locked
```

Run an advisory scanner and license-policy scanner when installed and
configured. Record exact commands and results. If unavailable, state that the
checks were not performed; never imply that `cargo check` covers known
vulnerabilities, malicious releases, maintainership or source provenance.

The current repository-wide dependency independence/mirroring decision is in
[platform vision decisions](../07.research-and-notes/13.platform-vision-record.en.md).
Required package files are introduced as packages are reviewed; the inventory
of packages still missing this record belongs in the work plan.
