# Add state

Keep business state in Rust services and data models. A route or panel action validates input, checks authorization and calls the service. The server remains the authority for protected data.

The current Live runtime can issue permission-scoped snapshots and dispatch signed typed actions. Browser-side reconciliation and shared replay protection are unfinished. Do not rely on client state as an authorization check.

See [The Basics of State](../03.core-concepts/03.the-basics-of-state.en.md) and the [authorization guide](../technical/03.for-developers/07.authorization.en.md).
