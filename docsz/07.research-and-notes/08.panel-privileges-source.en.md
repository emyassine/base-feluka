## Principes

1. **On n'écrit que de la logique métier.** Routes, permissions, sidebar, schémas SDUI, manifests et fichiers de config sont générés à la compilation.
2. **Zéro registre manuel, zéro string magique.** Tout passe par des attributs (`#[panel]`, `#[resource]`, `#[permissions]`, `#[gate]`…) collectés par le scanner de compilation, comme ton `profile_registry`.
3. **Le contexte est implicite.** Le module courant est connu du scanner, donc on ne le répète jamais (`Refund`, pas `sales.refund`) mais on peut le permettre on s'en fout.
3.1. On peut permettre al composition de roles par default sans trop ecrire de code genre <module><role>.<permission> but its is a whole a single permission comme ca dans chaque panel on injecte une resource de gestion des privileges/roles/permissions comme ca la personne habilitée peut créer des coles
3.2. Les provileges sont comme dans exemple php ancien qu'on avait en bas.
4. **Sécurisé par défaut.** Un handler qui modifie des données sans `#[gate]` ne compile pas.
5. **Un fichier = une responsabilité.** Une ressource = un fichier. Pas de `mod.rs` ni de `admin.rs` fourre-tout.
6. **Namespace unique** : `feluqa::ui`, `feluqa::panel`, `feluqa::auth`, `feluqa::resource`. Aucun `feluqa_*`.

## Arborescence

```text
my-erp/
├── Cargo.toml
└── src/
    ├── main.rs
    ├── panels/
    │   ├── back_office.rs            # /admin
    │   └── customer_portal.rs        # /app
    └── modules/
        └── sales/                    # id = nom du dossier
            ├── permissions.rs        # seulement les permissions custom
            ├── models/customer.rs
            ├── services/refunds.rs   # logique métier + #[gate]
            └── resources/
                ├── customer.rs       # form + table + actions + policy
                └── customer/edit.rs  # SEULEMENT si tu surcharges une page
```

**Généré, jamais édité, jamais committé** (dans `target/feluqa/`) : manifests de modules, table de routes, table de permissions, schémas de config, `.env.example`, docs de référence.

Le contrat de contexte actuel (`feluqa.toml` pour un produit, `module.toml` pour un module) reste valide. Ces fichiers deviennent de simples marqueurs écrits une fois par `feluqa new` / `make:module`, jamais maintenus à la main. Leur contenu est dérivé des attributs et de `Cargo.toml`.

## `main.rs`

```rust
#![no_implicit_prelude]
#![deny(unsafe_code, missing_docs)]

extern crate feluqa;

/// Point d'entrée. Découvre `src/panels` et `src/modules` par convention.
/// Génère le runtime, la CLI (`feluqa dev|migrate|…`), les routes et les permissions.
#[feluqa::main]
fn main() {}
```

Les chemins ne s'écrivent que pour s'écarter de la convention : `#[feluqa::main(panels = "src/ui/panels")]`.

## Un module

Le module n'a besoin de rien : le dossier `modules/sales/` suffit (id = `sales`, version = celle de `Cargo.toml`). Un fichier `module.rs` n'existe que pour déclarer des dépendances :

```rust
feluqa::module! { requires = ["core >= 1"] }
```

## Permissions : déclarées par attribut, jamais hardcodées

```rust
// src/modules/sales/permissions.rs

/// Permissions du domaine Ventes.
/// NOTE: les permissions CRUD des ressources (`view_any`, `view`, `create`, `update`,
/// `delete`…) sont générées automatiquement par `#[resource]`. N'ajouter ici que les
/// permissions métier qui ne correspondent à aucune ressource.
#[feluqa::permissions]
pub enum Sales {
    /// Rembourser une commande payée.
    Refund,
    /// Exporter le grand livre comptable.
    ExportLedger,
}
```

- Le nom complet (`sales.refund`) est construit à la compilation à partir du module courant.
- **La doc-comment est obligatoire** : elle devient le libellé affiché dans le System panel. Sans doc, erreur de compilation.
- Le System panel lit la table générée. Aucune permission n'est créée à la main ni en base de seed.
- Utilisation typée : `ctx.user().can(Sales::Refund)`.

## `#[gate]` : protéger une fonction

On ajoute l'attribut au-dessus de la logique métier. Le module courant est résolu tout seul.

```rust
// src/modules/sales/services/refunds.rs

/// Rembourse une commande payée.
/// Refusé (`Denied`) si l'utilisateur n'a pas `sales.refund`.
#[feluqa::gate(require_permission = Refund)]
pub async fn refund_order(ctx: &Ctx, order: OrderId) -> Result<Refund> {
    // Ici, uniquement la logique métier.
    // Le contrôle d'accès, l'audit log et l'erreur 403 sont injectés par la macro.
    ctx.db().orders().refund(order).await
}
```

**Syntaxe** : un attribut Rust utilise `=` et non `:`, donc `require_permission = Refund`.

**Résolution de l'argument** (ordre fixe, erreur de compilation avec suggestion si introuvable) :
1. une capacité de la ressource englobante (`view_any`, `delete`…) ;
2. une permission du module courant (`Refund`) ;
3. une permission d'un autre module, avec chemin explicite (`billing::Invoice`) ;
4. une permission de la plateforme (`platform::ManageModules`).

**Options disponibles :**

```rust
#[feluqa::gate(require_permission = Refund)]                    // une permission
#[feluqa::gate(require_any = [Refund, ExportLedger])]           // OU
#[feluqa::gate(require_role = Finance)]                         // rôle déclaré par #[roles]
#[feluqa::gate(require_tenant)]                                 // doit avoir un tenant actif
#[feluqa::gate(authenticated)]                                  // connecté, sans permission précise
#[feluqa::gate(public)]                                         // ouvert, et c'est un choix explicite
#[feluqa::gate(require_permission = Refund, on_deny = hide)]    // UI: masque au lieu d'erreur
```

Plusieurs `#[gate]` empilés se combinent en **ET**.

**Où on peut le poser :** fonctions de services, hooks de ressource, handlers d'API (`#[feluqa::get("/orders/{id}")]`), actions, pages custom.

**Secure by default** : une fonction annotée `#[feluqa::post]`, `#[feluqa::action]` ou un hook d'écriture sans `#[gate]` est une erreur de compilation. Pour l'ouvrir, il faut écrire `#[gate(public)]`, visible en revue de code.

**Équivalent builder** pour l'UI dynamique : `Action::make("refund").gate(Sales::Refund)`. C'est la même règle, et elle alimente le même registre.

## Un panel (équivalent de `AdminPanelProvider`)

```rust
// src/panels/back_office.rs
use feluqa::panel::{Panel, NavGroup, Colors, DarkMode, Width, Hook};
use feluqa::auth::{Auth, Login};
use feluqa::ui::{self, Icon};

/// Panel d'administration interne, servi sur `/admin`.
/// NOTE: ce panel ne liste AUCUNE ressource. Chaque `#[resource(panel = "admin")]`
/// s'y rattache toute seule. Les groupes de navigation ci-dessous ne sont que de la présentation.
#[feluqa::panel(id = "admin", path = "/admin")]
pub fn back_office(panel: Panel) -> Panel {
    panel
        .brand("Feluqa ERP")
        .logo(feluqa::asset!("logo.svg"))
        .favicon(feluqa::asset!("favicon.png"))
        .font("Inter")
        .colors(Colors::new().primary("#6366f1").danger("rose").success("emerald"))
        .dark_mode(DarkMode::System)
        .max_content_width(Width::Full)
        .login(Login::default())
        .registration()
        .password_reset()
        .email_verification()
        .tenant::<Team>()
        .middleware(Auth::session())
        .spa().prefetch()
        .unsaved_changes_alerts()
        .database_transactions()
        .navigation_groups([
            NavGroup::new("Shop").icon(Icon::ShoppingCart),
            NavGroup::new("Blog").icon(Icon::Pencil),
            NavGroup::new("Settings").icon(Icon::Cog).collapsed(),
        ])
        .render_hook(Hook::BodyStart, || ui::slot("modal-host"))
}
```

L'autorisation stricte est le comportement **par défaut** (pas de `.strict_authorization()` à écrire). `.permissive_authorization()` existe pour les prototypes et est refusé en profil `production`.

## Une ressource (CRUD complet en un fichier)

```rust
// src/modules/sales/resources/customer.rs
use feluqa::resource::prelude::*;
use feluqa::ui::{form::*, Icon};
use super::super::models::Customer;

/// Clients de l'entreprise.
/// Génère: routes `/admin/customers[/create|/{record}/edit]`, pages List/Create/Edit,
/// entrée de sidebar, permissions `sales.customers.*`, schéma SDUI multi-cible.
#[feluqa::resource(panel = "admin", group = "Shop", icon = Icon::Users)]
pub struct CustomerResource;

impl Resource for CustomerResource {
    type Model = Customer;

    fn form(form: Form) -> Form {
        form.schema([
            TextInput::make(Customer::NAME).required().max_length(120),
            TextInput::make(Customer::EMAIL).email().required().unique(),
            Select::make(Customer::COUNTRY).options(Country::all()).searchable(),
            Toggle::make(Customer::ACTIVE).default(true),
        ])
    }

    fn table(table: Table) -> Table {
        table
            .columns([
                Column::make(Customer::NAME).searchable().sortable(),
                Column::make(Customer::EMAIL).copyable(),
                Column::badge(Customer::STATUS),
            ])
            .filters([
                Filter::make("verified").query(|q| q.where_not_null(Customer::VERIFIED_AT)),
            ])
            .record_actions([EditAction::make(), DeleteAction::make()])
            .bulk_actions([BulkActions::group([DeleteBulk::make()])])
            .default_sort(Customer::CREATED_AT, Desc)
    }

    /// Hook métier. Le gate `create` est déjà appliqué par la ressource.
    async fn before_create(data: &mut CustomerData, ctx: &Ctx) -> Result<()> {
        data.owner_id = ctx.user().id;
        Ok(())
    }
}

/// Règles par enregistrement uniquement.
/// NOTE: ne pas re-tester la permission ici. `sales.customers.delete` est déjà vérifiée
/// avant, et la policy s'y ajoute en ET.
#[feluqa::policy(Customer)]
impl CustomerPolicy {
    fn delete(_user: &User, c: &Customer) -> bool { !c.has_open_orders() }
}
```

**La sidebar est le contrôle d'accès.** L'entrée « Customers » apparaît seulement si l'utilisateur a `sales.customers.view_any`. Les boutons d'actions suivent leur capacité. Le schéma SDUI envoyé au client est déjà filtré côté serveur. Masquer côté client n'est jamais une protection, et le gate serveur s'applique toujours.

## Niveau 0 : zéro config

```rust
/// Client. Un CRUD complet avec table, formulaire, routes et permissions.
#[derive(feluqa::Model, feluqa::Resource)]
#[resource(panel = "admin", group = "Shop")]
pub struct Customer {
    #[field(text, required, searchable)] pub name: String,
    #[field(email, required, unique)]    pub email: String,
    #[field(toggle, default = true)]     pub active: bool,
}
```

On passe au niveau 1 (le `impl Resource`) seulement quand on a besoin de contrôle.

## Surcharger une page (seulement si nécessaire)

```rust
// src/modules/sales/resources/customer/edit.rs

/// Édition d'un client avec stats et sous-navigation.
#[feluqa::page(resource = CustomerResource, kind = Edit)]
pub fn edit(page: Page<Customer>) -> Page<Customer> {
    page
        .title(|c| format!("Éditer {}", c.name))
        .header_actions([
            Action::make("impersonate").gate(platform::Impersonate),
        ])
        .widgets([CustomerStats::for_record()])
        .sub_navigation([Tab::new("Général"), Tab::new("Commandes").badge(|c| c.orders_count())])
}
```

Une page entièrement libre (`#[feluqa::page(custom)]` avec `view!` Leptos) est l'exception. Dans les formulaires et tables, on reste en builders SDUI, sinon le rendu web/mobile/desktop ne fonctionne plus.

## Config : générée, typée

```rust
/// Paramètres de la base. Valeurs lues dans l'environnement, jamais dans le code.
#[feluqa::config(prefix = "DATABASE")]
pub struct Database {
    /// URL de connexion (secret).
    pub url: Secret<String>,
    /// Taille du pool.
    #[config(default = 10)] pub pool: u32,
}
```

Le schéma, `.env.example`, la validation au démarrage et la page de config du System panel sont générés. Fini `app.{development,staging,production}.toml`, `config.rs`, `database.*.toml`.

## Ce qui passe à la compilation

| Avant (legacy panel implementation / manuel) | Feluqa |
|---|---|
| `discoverResources(in:, for:)` | scanner d'attributs, registre `static` |
| `'name'` en string | constantes `Customer::NAME` |
| Permissions créées en base | `#[permissions]` + ressources, table générée |
| `user.can("sales.refund")` | `Sales::Refund`, vérifié par le compilateur |
| Policy absente = accès ouvert | gate obligatoire, sinon erreur de compilation |
| Routes enregistrées au boot | table `const` |
| Providers / `register_*` | `#[panel]`, `#[resource]`, `#[page]` suffisent |
| Fichiers `*.toml` d'environnement | `#[config]` + `.env.example` généré |
| `module.toml` maintenu à la main | dérivé du dossier, de `Cargo.toml` et de `module!{}` |

## Extensions du core nécessaires (on est en dev actif)

1. **Module connu statiquement.** Le scanner génère dans chaque module une constante cachée (`__MODULE_ID`, dérivée de `src/modules/<id>/`). C'est ce que les macros `#[gate]`, `#[permissions]` et `#[resource]` utilisent pour préfixer les noms. Un proc-macro ne peut pas deviner de façon fiable le chemin du fichier source sur Rust stable, donc on passe par le scanner plutôt que par un hack de `Span`.
2. **`FeluqaContext` reconnaît le manifeste généré** comme marqueur de module et de produit, en plus de `module.toml` et `feluqa.toml`. Le loader de la plateforme confirme l'ID au runtime ; le scanner le fournit à la compilation. Les deux doivent coïncider, sinon le module est refusé.
3. **Façade `feluqa::storage_path()` / `ctx.storage()`** résolue via cet ID : `<product-or-platform>/storage/modules/<module-id>`. Une crate sans propriétaire de module reste une erreur, jamais une devinette.
4. **Table de permissions** consommée par le System panel (installation, activation et désactivation par domaine, affectation aux rôles).

## Règles pour développeurs et agents

Ces règles seront aussi générées dans `AGENTS.md` par `feluqa new`.

- **Documente tout.** `#![deny(missing_docs)]` est actif. Chaque item `pub`, chaque permission, chaque ressource, panel et page porte une `///`. Ces docs alimentent le System panel, l'aide CLI et `feluqa docs`. Explique le *pourquoi* métier, pas la syntaxe.
- **Ne tiens jamais de registre à la main** (listes de routes, de permissions, de ressources). Si tu en ressens le besoin, il manque un attribut : signale-le au lieu de contourner.
- **Pas de string pour un champ, une permission ou un rôle.** Utilise `Customer::NAME`, `Sales::Refund`.
- **Pas de fichier de config à écrire.** Ajoute un `#[config]` typé.
- **Tout handler qui écrit porte un `#[gate]`.** `public` doit être justifié en commentaire.
- **Ne répète pas le contexte.** Dans un module, écris `Refund`, pas `sales.refund`. Le chemin complet n'est utile que pour un autre module.
- **Un seul fichier par ressource.** Crée `resource/<nom>/edit.rs` uniquement pour surcharger une page.
- **Pour générer, utilise la CLI :** `feluqa make:module sales`, `make:resource Customer --from-model`, `make:panel customer_portal --path=/app`, `make:page edit --resource=customer`. Chaque commande produit un seul fichier.
- **Termine par `feluqa check`** (compilation, gates manquants, docs manquantes, permissions orphelines).

Si tu veux, je peux écrire la suite : les signatures des traits `Resource` / `Panel` et des builders `Form` / `Table` pour valider que le chaînage compile, ou le contrat de la macro `#[gate]` (ce qu'elle injecte, comment elle trouve `ctx`, erreurs de compilation attendues).

EXEMPLE PHP DES USER PRIVILEDGE LEVELS (pas obligé d'avoir tout ca mais je pense bien notamenert pour les applications militaires or such d'avoir une question de privilege)

<?php declare(strict_types=1);

namespace Webkernel\Base\Users\Enums;

/**
 * ════════════════════════════════════════════════════════════════════════════
 * UserPrivilegeLevel
 * ════════════════════════════════════════════════════════════════════════════
 *
 * Defines the privilege levels of users WITHIN THE WEBKERNEL PLATFORM INSTANCE.
 *
 * ┌─────────────────────────────────────────────────────────────────────────┐
 * │  SCOPE OF THIS ENUM                                                     │
 * │                                                                         │
 * │  This enum governs platform-level access only:                          │
 * │  → Who can manage the platform itself (settings, modules, billing…)     │
 * │  → Who can configure or administer the instance                         │
 * │                                                                         │
 * │  This enum does NOT govern:                                             │
 * │  → End-users inside modules (hotels, banks, SaaS apps…)                │
 * │  → Module-level customers, sub-customers, or their admins               │
 * │  → Fine-grained permissions within a module                             │
 * │                                                                         │
 * │  Module-level access is handled by a dedicated Role/Permission system   │
 * │  (RBAC) that each module can extend independently.                      │
 * └─────────────────────────────────────────────────────────────────────────┘
 *
 * ── Privilege Levels ────────────────────────────────────────────────────────
 *
 * Each level exists in TWO variants: INTERNAL and EXTERNAL.
 * Internal = direct organisation member managed by Webkernel.
 * External = contractor, auditor, integrator, service provider…
 *
 * IMPORTANT — Rank vs Origin:
 *   • The RANK (hierarchy weight) is the same for internal and external
 *     variants at equivalent levels. A SUPER_ADMIN is a SUPER_ADMIN.
 *   • The ORIGIN (internal/external) is a separate attribute (@see UserOrigin)
 *     used by the app owner to control visibility, feature access, or UI.
 *   • APP_OWNER is strictly reserved for INTERNAL users. There is no
 *     external equivalent of the application owner.
 *
 * ── Hierarchy (rank) ────────────────────────────────────────────────────────
 *
 *   APP_OWNER      (60)  — internal only
 *   SUPER_ADMIN    (50)  — internal & external share this rank
 *   SYSADMIN       (40)  — internal & external share this rank
 *   STAFF          (30)  — internal & external share this rank
 *
 * ── Naming clarification ────────────────────────────────────────────────────
 *
 *   STAFF replaces the former "MEMBER" to avoid ambiguity.
 *   "Member" is reserved for module-level end-user concepts.
 *   STAFF = a platform-level team member (internal or external collaborator).
 *
 * @see UserOrigin  for the internal/external discriminator.
 */
enum UserPrivilegeLevel: string
{
    // ── Internal ──────────────────────────────────────────────────────────────

    /** Full platform ownership. One per instance. Internal only. */
    case APP_OWNER  = 'app-owner';

    /** Full administrative access, internal team. */
    case SUPER_ADMIN = 'super-admin';

    /** Technical/infrastructure administrator, internal. */
    case SYSADMIN   = 'sysadmin';

    /** Standard platform team member, internal. */
    case STAFF      = 'staff';

    // ── External (contractors, auditors, integrators, service providers…) ─────

    /** Full administrative access, externally contracted. Same rank as SUPER_ADMIN. */
    case EXTERNAL_SUPER_ADMIN = 'external-super-admin';

    /** Technical administrator, externally contracted. Same rank as SYSADMIN. */
    case EXTERNAL_SYSADMIN    = 'external-sysadmin';

    /** Standard collaborator, externally contracted. Same rank as STAFF. */
    case EXTERNAL_STAFF       = 'external-staff';


    // ════════════════════════════════════════════════════════════════════════
    // Labels & descriptions
    // ════════════════════════════════════════════════════════════════════════

    public function label(): string
    {
        return match ($this) {
            self::APP_OWNER           => 'Application Owner',
            self::SUPER_ADMIN         => 'Super Administrator',
            self::SYSADMIN            => 'System Administrator',
            self::STAFF               => 'Staff Member',
            self::EXTERNAL_SUPER_ADMIN => 'External Super Administrator',
            self::EXTERNAL_SYSADMIN   => 'External System Administrator',
            self::EXTERNAL_STAFF      => 'External Collaborator',
        };
    }

    public function description(): string
    {
        return match ($this) {
            self::APP_OWNER =>
                'Ultimate authority over the platform instance. ' .
                'Reserved for internal users only. Cannot be assigned externally.',
            self::SUPER_ADMIN =>
                'Full administrative access to all platform features and modules (internal).',
            self::SYSADMIN =>
                'Technical control over infrastructure, integrations and system configuration (internal).',
            self::STAFF =>
                'Standard authenticated platform team member with role-assigned permissions (internal).',
            self::EXTERNAL_SUPER_ADMIN =>
                'Full administrative access, equivalent to Super Admin, granted to an external contractor or partner.',
            self::EXTERNAL_SYSADMIN =>
                'Technical system access equivalent to SysAdmin, granted to an external provider or auditor.',
            self::EXTERNAL_STAFF =>
                'Standard collaborator access equivalent to Staff, granted to an external contractor.',
        };
    }


    // ════════════════════════════════════════════════════════════════════════
    // Rank & Hierarchy
    // ════════════════════════════════════════════════════════════════════════

    /**
     * Numeric rank. Higher = more privileged.
     *
     * Internal and external equivalents share the same rank intentionally:
     * privilege level is orthogonal to origin.
     *
     *   APP_OWNER              60   (no external equivalent)
     *   SUPER_ADMIN            50   ↔  EXTERNAL_SUPER_ADMIN  50
     *   SYSADMIN               40   ↔  EXTERNAL_SYSADMIN     40
     *   STAFF                  30   ↔  EXTERNAL_STAFF        30
     */
    public function rank(): int
    {
        return match ($this) {
            self::APP_OWNER                                => 60,
            self::SUPER_ADMIN, self::EXTERNAL_SUPER_ADMIN  => 50,
            self::SYSADMIN,    self::EXTERNAL_SYSADMIN     => 40,
            self::STAFF,       self::EXTERNAL_STAFF        => 30,
        };
    }

    /** True when $this ranks strictly above $other (regardless of origin). */
    public function isAbove(self $other): bool
    {
        return $this->rank() > $other->rank();
    }

    /** True when $this ranks at least as high as $other. */
    public function isAtLeast(self $other): bool
    {
        return $this->rank() >= $other->rank();
    }

    /** True when $this ranks strictly below $other. */
    public function isBelow(self $other): bool
    {
        return $this->rank() < $other->rank();
    }

    /** True when both levels share the same rank (equivalent privilege-wise). */
    public function isEquivalentTo(self $other): bool
    {
        return $this->rank() === $other->rank();
    }


    // ════════════════════════════════════════════════════════════════════════
    // Origin helpers
    // ════════════════════════════════════════════════════════════════════════

    public function origin(): UserOrigin
    {
        return match ($this) {
            self::APP_OWNER,
            self::SUPER_ADMIN,
            self::SYSADMIN,
            self::STAFF              => UserOrigin::INTERNAL,
            self::EXTERNAL_SUPER_ADMIN,
            self::EXTERNAL_SYSADMIN,
            self::EXTERNAL_STAFF     => UserOrigin::EXTERNAL,
        };
    }

    public function isInternal(): bool
    {
        return $this->origin() === UserOrigin::INTERNAL;
    }

    public function isExternal(): bool
    {
        return $this->origin() === UserOrigin::EXTERNAL;
    }

    /** @deprecated Use isInternal() instead. */
    public function isInternalOnly(): bool
    {
        return $this->isInternal();
    }

    /** @deprecated Use isExternal() instead. */
    public function isExternalLevel(): bool
    {
        return $this->isExternal();
    }


    // ════════════════════════════════════════════════════════════════════════
    // Equivalence & scope queries
    // ════════════════════════════════════════════════════════════════════════

    /**
     * Returns all privilege levels that are equivalent in rank to $this,
     * optionally filtered by origin scope.
     *
     * @param  'internal'|'external'|'both'  $scope
     * @return list<self>
     *
     * Examples:
     *   SUPER_ADMIN->orEquivalent('both')      → [SUPER_ADMIN, EXTERNAL_SUPER_ADMIN]
     *   EXTERNAL_SYSADMIN->orEquivalent('internal') → [SYSADMIN]
     *   STAFF->orEquivalent('external')        → [EXTERNAL_STAFF]
     */
    public function orEquivalent(string $scope = 'both'): array
    {
        return $this->filterByRankAndScope($this->rank(), $scope, strict: false);
    }

    /**
     * Returns all levels that rank at or above $this,
     * optionally filtered by origin scope.
     *
     * @param  'internal'|'external'|'both'  $scope
     * @return list<self>
     */
    public function atOrAbove(string $scope = 'both'): array
    {
        $rank = $this->rank();

        return array_values(array_filter(
            self::allByRank(),
            fn (self $c) => $c->rank() >= $rank && $this->matchesScope($c, $scope),
        ));
    }

    /**
     * Returns all levels that rank strictly below $this,
     * optionally filtered by origin scope.
     *
     * @param  'internal'|'external'|'both'  $scope
     * @return list<self>
     */
    public function below(string $scope = 'both'): array
    {
        $rank = $this->rank();

        return array_values(array_filter(
            self::allByRank(),
            fn (self $c) => $c->rank() < $rank && $this->matchesScope($c, $scope),
        ));
    }


    // ════════════════════════════════════════════════════════════════════════
    // Collections & option lists
    // ════════════════════════════════════════════════════════════════════════

    /** @return list<self> All internal levels, ordered high → low. */
    public static function internalLevels(): array
    {
        return [self::APP_OWNER, self::SUPER_ADMIN, self::SYSADMIN, self::STAFF];
    }

    /** @return list<self> All external levels, ordered high → low. */
    public static function externalLevels(): array
    {
        return [self::EXTERNAL_SUPER_ADMIN, self::EXTERNAL_SYSADMIN, self::EXTERNAL_STAFF];
    }

    /** @return list<self> All levels ordered by rank descending. */
    public static function allByRank(): array
    {
        $cases = self::cases();
        usort($cases, fn (self $a, self $b) => $b->rank() <=> $a->rank());
        return $cases;
    }

    /** @return array<string, string> value → label map for all levels. */
    public static function options(): array
    {
        return array_column(
            array_map(fn (self $c) => [$c->value, $c->label()], self::allByRank()),
            1, 0,
        );
    }

    /** @return array<string, string> */
    public static function internalOptions(): array
    {
        return array_column(
            array_map(fn (self $c) => [$c->value, $c->label()], self::internalLevels()),
            1, 0,
        );
    }

    /** @return array<string, string> */
    public static function externalOptions(): array
    {
        return array_column(
            array_map(fn (self $c) => [$c->value, $c->label()], self::externalLevels()),
            1, 0,
        );
    }

    /** Returns null if the key does not match any case (no exception). */
    public static function fromKey(string $key): ?self
    {
        return self::tryFrom($key);
    }


    // ════════════════════════════════════════════════════════════════════════
    // Private helpers
    // ════════════════════════════════════════════════════════════════════════

    private function filterByRankAndScope(int $rank, string $scope, bool $strict): array
    {
        return array_values(array_filter(
            self::allByRank(),
            fn (self $c) => $c->rank() === $rank && $this->matchesScope($c, $scope),
        ));
    }

    /**
     * @param  'internal'|'external'|'both'  $scope
     * @throws \InvalidArgumentException on unknown scope value.
     */
    private function matchesScope(self $case, string $scope): bool
    {
        return match ($scope) {
            'internal' => $case->isInternal(),
            'external' => $case->isExternal(),
            'both'     => true,
            default    => throw new \InvalidArgumentException(
                "Invalid scope \"{$scope}\". Expected: 'internal', 'external', or 'both'.",
            ),
        };
    }
}
